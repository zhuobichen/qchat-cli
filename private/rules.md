# 长期规则（人工维护）

> 这些是跨会话要记住的东西。每轮回答前都会读人格文件，所以规则主要写在
> `private/personas/global.md` 里；这里放更长的案例和来龙去脉。

---

## 1. 不确定就搜，别凭记忆下结论

**规则**：只要答案是"没有 / 做不到 / 不支持"，先联网搜。

**为什么**：记忆里的"没有"通常只是"我当时不知道"。软件生态一年就变样，
三年前的印象基本作废。

**必须搜的几类**：

| 类型 | 例子 |
|---|---|
| 版本与能力 | 某模组支不支持某协议、某库有没有某 API |
| 有没有现成方案 | "有没有人做过 X" |
| 价格/限制 | 某服务免费额度、某模型上下文长度 |
| 维护状态 | 开源项目还在不在更新 |

**反面案例（2026-11-07，车万女仆）**

群里问"有没有把 agent 接入车万女仆的教程"。

我的回答：*"没有现成的 agent 接入教程——它没有对外的对话接口，要接只能改模组源码。"*

搜完的真实情况：

1. **模组本体就带 AI 聊天**，支持三种协议（Chat Completions / Responses /
   Anthropic Messages），填 URL + Key 就能接任意 LLM 端点
2. **[maid-cli](https://www.jiaoben.net/wz/758948.html)** —— 专门给 agent 用的
   HTTP 控制层，`127.0.0.1:8644`，27 条指令，`/help` 自省，不用硬编码工具定义。
   能读女仆的血量/背包/视线/周围实体，能下走路/挖/放/骑乘指令，能开会话操作容器
3. **[Agent 功能拓展](https://m.mcmod.cn/class/31858.html)** —— 思考链显示、
   Token 明细、费用统计、手动压缩聊天记录

**我错了三个数量级**：从"要改源码"到"填个 URL 就行"。

**教训**：技术类问题里，"不可能"这个结论的成本最高——说错了会让人多走几条弯路。

## 1b. 先搜自己的仓库，再搜互联网

**顺序不能反。**

```text
① grep 自己的项目（src/ scripts/ private/）
② 查依赖/工具本身的接口
③ 联网搜
```

反面案例（2026-11-07，QQ空间）：有人问"能看别人 QQ 空间吗"，我第一反应是去测
NapCat 的 OneBot 接口，发现没有，正准备答"不行"。

实际上 `qchat-cli` 里早就有：
- `src/commands/qzone.ts` —— 15 个子命令（user / feeds / blogs / post / visitors / board / like / comments / albums …）
- `src/core/qzone-client.ts` —— 客户端实现
- `private/qzone-ops.mjs` —— 说明之前就折腾过

**功能在我自己的项目里，我却去外面找。**

这是比"记忆过时"更低的错误：连代码库都没看。

## 2. 别把"该不该回"和"能不能改"搞混

- **该不该回**：对所有人一样，判断该回才回
- **能不能改**：只有主人（1473517806）能让我改人格/参数/功能

我第一版把"主人权限高"实现成了"主人发消息必回"，被纠正了。

## 3. 长期任务先回执，再后台跑

超过 30 秒的活（生图、点歌、转写、打标）不能阻塞等待：
先回一句"在做"，后台跑完再补结果。

要交付到 QQ 的用 `scripts/task.mjs`——任务进程自己投递，不怕 agent 不在场。
