# 能力分三层

别混在一起记。混起来的结果是：一个 "skill 文档" 里塞进了 `qce send` 这种天生就会的命令，
而真正需要说明的"这个外部能力从哪来、要不要授权"反而没写。

## 第一层：基础设施（本仓库自带，不是技能）

**这是 qchat-cli 这个库本身的功能**，用 `node dist/cli.js <命令>` 调。不需要安装、不需要授权。

```
收发消息       qce send group|msg
历史索引       qce index / qce search / qce digest
群成员         qce list / qce friend
子进程/文件/网络  环境天生就有，不登记
```

**详细地图：** [`qchat-skills/SKILL.md`](./qchat-skills/SKILL.md)（14 类，含每条踩过的坑）

## 第二层：外部能力（要装、要引、要授权）

跟这个库没关系，是"装进来的东西"。

| 名称 | 来源 | 装在哪 | 需不需要授权 | 备注 |
|---|---|---|---|---|
| **carl-motion** | [LearnPrompt/carl-motion](https://github.com/LearnPrompt/carl-motion)（MIT / 演示片 CC BY 4.0） | `skills/carl-motion/` | 否（纯本地渲染） | 29 种动效画风，20 个引擎带源码 |
| **豆包桌面版** | 本机安装 | `D:\豆包\` | **是**（要用账号额度） | 生图 30 秒 / 生视频 6-16 分钟 |
| **rapidocr** | pip | 系统 Python | 否 | 图片转文字 |
| **faster-whisper** | pip | 系统 Python | 否 | 语音转文字 |

**外部能力的判断标准：** 换一台空机器就直接失效的，就是外部能力。

## 第三层：MCP

跟"技能"是两回事：**MCP 是协议，技能是文档。**

| 服务器 | 干什么 | 谁在用 |
|---|---|---|
| `aram-mayhem` | 海克斯大乱斗数据（战绩、符文、出装） | 群里的开黑话题 |
| `tencent-docs` | 腾讯文档读写 | 需要建文档时 |
| `tencent-qqmail` | QQ 邮箱 | 需要收信时 |
| `weflow` | 微信本地数据 | 需要跨平台查时 |
| `craft-anything` | 逆向/取证工作台 | 需要拆二进制时 |
| `blender_rt` | Blender 实时驱动 | 3D 建模时 |
| `ig5` | 二进制静态分析 | 同上 |

**MCP 的特点：** 工具调用会产生真实副作用（发文档、发邮件），
**动手前要确认，不是"看到了就能随便调"。**
